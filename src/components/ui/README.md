# UI primitives

These are the shadcn primitives, kept where the shadcn CLI expects them (`aliases.ui` in `components.json`) and edited in place. They are private to the kit: product code imports them through `@/components/patterns` (DESIGN.md, Components). This file logs every place a primitive differs from what the CLI generates, so a later `npx shadcn add <name>` can be merged by hand without losing the edits below. Read it before re-adding a component, and add a line here in the same change as any new edit.

## Rules every primitive follows

These hold for every file in this folder. A re-added component must be brought back in line with them.

- **Tokens only.** Colour, shadow and radius come from the semantic tokens in `src/index.css` (DESIGN.md, Colour). No palette classes (`bg-black/80`, `text-white`), no default shadows (`shadow-xs`…`shadow-lg`): cards use `shadow-card`, floating surfaces `shadow-popover`, scrims `bg-overlay`.
- **No `transition-all`.** List the property (`transition-colors`, `transition-opacity`, `transition-transform`) and use `duration-150`.
- **Focus rings on `focus-visible:` only**, with `outline-hidden` instead of `outline-none`, so the ring survives Windows forced-colours mode. Upstream's Dialog and Sheet close buttons, Select trigger and Badge used `focus:`.
- **Targets.** Fine pointers get dense controls with a 24px floor. The `coarse:` variant (`@media (pointer: coarse)`, defined in `src/index.css`) lifts every interactive primitive to 44px, usually with a `min-h-11` / `min-w-11` floor so call-site `h-*` / `w-*` overrides still win. It replaced the old `max-md:min-h-*` and `max-md:py-2.5` width-based bumps.
- **Window size classes, not default breakpoints.** Upstream's `sm:` (640px) becomes `medium:` (600px) in Dialog, AlertDialog and Sheet: rounded corners, left-aligned headers, row footers and the Sheet's `max-w-sm` start 40px sooner. Calendar's `md:` (768px) becomes `expanded:` (840px), so two months side by side always fit; between 768px and 839px the months stack with 44px cells. Primitives don't use `@container`: Calendar sits in content-sized popovers, where a size container collapses.
- **Focus rings are opaque `ring-ring`**, not upstream's `ring-ring/50`, so the ring meets 3:1 against `background` and `card` (checked in `src/styles/contrast.test.ts`). Button's ring is `ring-2` with a 2px `ring-offset-background` gap, like the inputs: an opaque ring flush against a `primary` fill would read as a bigger button.
- **Control heights** are `sm` 32px, `default` 36px, `lg` 44px, with inputs matching buttons at each size.
- **Motion.** Overlays animate with `tw-animate-css` keyframes, entering in `duration-200 ease-out` and exiting in `duration-150 ease-in`, written per state (`data-[state=open]:duration-200 data-[state=open]:ease-out data-[state=closed]:duration-150 data-[state=closed]:ease-in`). Upstream uses one `duration-200` (Dialog) or `duration-500` / `duration-300` (Sheet) for both directions. The global reduced-motion rule in `src/index.css` makes overlays instant and leaves `animate-spin` running.
- **Radix CSS variables use the v4 syntax** `origin-(--radix-…)`. The v3 form `origin-[--radix-…]` that older generated files carry produces invalid CSS in Tailwind v4.

## Known gaps

- `sonner.tsx` keeps the `toaster` class, which its `group-[.toaster]:` selectors need; it stays in `eslint-suppressions.json`. So do `mobile-calendar` (defined in `responsive-date-picker.css`) and the ghost `pb-safe` class in `responsive-date-picker.tsx`.
- `max-md:text-base` on inputs uses a default breakpoint; it moves to the window size classes with slice 6.
