# A cabin's state is derived from bookings and blocks, not stored

A unit stores no status. Whether a cabin is blocked, booked or free on a date comes only from its blocks and confirmed bookings, and the cabin screen shows that derived state for tonight. We removed `units.unit_status` (Available / Occupied / Maintenance / Reserved) because staff set it by hand, every booking path read any non-Available value as "unbookable on every date", and it bypassed the block conflict rules: marking a cabin Maintenance stranded its future bookings without warning. An outage of unknown length is a block with an estimated end date that staff extend. We rejected an open-ended block (nullable end date) because it reopens the block model, the conflict trigger and every range query. The column goes in two releases: first nothing reads or writes it, then it is dropped. Retiring a cabin for good has no replacement yet; when it is needed, it is a separate in-service flag, not a block and not a return of the status column.
