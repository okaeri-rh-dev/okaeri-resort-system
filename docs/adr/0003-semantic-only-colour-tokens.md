# Colour comes only from semantic tokens; the default Tailwind palette is removed

UI colour comes only from one layer of semantic tokens (shadcn-style `X` / `X-foreground` pairs, OKLCH values in top-level `:root` and `.dark` in `src/index.css`, mapped by `@theme inline`), and the end state resets Tailwind's defaults with `--color-*: initial`, `--shadow-*: initial` and `--font-*: initial`, so `bg-blue-500`, `shadow-md` and `font-mono` stop existing. We chose this over keeping the palette alongside the tokens because about 1,465 raw palette classes had drifted into 153 files, which produced three competing primaries and a dark mode that couldn't work. We also rejected a separate reference palette (`--hearth-timber-600`) because it would give agents a second set of names to reach for. The reset can't land first: Tailwind silently drops unknown classes, so a lint rule bans palette classes and `font-mono` from day one, with a per-file legacy allowlist that may only shrink, and the reset is the last step of the migration, once that allowlist is empty.
