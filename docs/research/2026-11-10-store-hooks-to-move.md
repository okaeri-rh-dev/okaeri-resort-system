# Store hooks to move: exports, importers, dead callers

Research for issue #402 (map #400, Candidate 6: stores keep only UI state). Question: which TanStack exports and optimistic-map actions live in each entity store, who imports them, which optimistic `cancelQueries`/`setQueryData` exist, are the logged dead old-format callers still dead, and which README lines go stale.

Sources: `main` at `33d5fb0d`. Line numbers are `main`. Importer lists come from `grep` for the export name in files that import the store module (`src`, `e2e`), plus `vi.mock` sites, which grep cannot see as imports. "Tests" below means files under `__tests__/` or `src/tests/`.

Decisions already made on #400 are not reopened: hooks move to flat `src/hooks/use<Entity>.ts`, imports change in the same PR with no re-exports, Zustand optimistic maps and the `App.tsx` cleanup timer go.

## Headline

- **Every Zustand optimistic map is a no-op today.** Bookings and guests never add an entry (`addOptimisticBooking`, `addOptimisticGuest` have no callers), and their `update…` actions only change an existing entry, so the status/guest "optimistic update" does nothing. The money maps (accounts, expenses, transfers) are written and never read. Units add entries, but the list query reads the map only while it fetches, and `onSuccess` removes the entry before `onSettled → afterWrite` refetches, so the list never shows it; the one real optimistic effect in units is `setQueryData` on the **detail** key. The `onMutate → setQueryData` on list keys that #400 decided on is therefore new behavior, not a port.
- **Logged dead callers are still dead** (no non-test caller): `db.bookings.update`, `db.bookings.checkMultiUnitAvailability`, store `checkUnitAvailability`, `checkMultiUnitAvailability`, `checkAllUnitsAvailability`. Also dead: `db.bookings.checkAvailability`, the multi-unit `availabilityCache` (only the realtime hook clears it; nothing reads it) and the multi-unit `optimisticQueue`/`bookings` map.
- **No name clash** in `src/hooks` for `useBookings.ts`, `usePayments.ts`, `useGuests.ts`, `useUnits.ts`, `useAccounts.ts`, `useExpenses.ts`, `useTransfers.ts`. Near names exist: `usePaymentMethods.ts`, `useExpenseCategories.ts`, `useCalendarBookings.ts`, `useMultiUnitBookingQueries.ts`.
